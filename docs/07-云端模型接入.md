# 07 云端模型接入

> **Cloud First** - 云端模型为主，本地模型为辅

## 为什么选择云端？

### 云端优势

| 对比 | 云端模型 | 本地模型 |
|------|---------|---------|
| **性能** | ⭐⭐⭐⭐⭐ 最新最强 | ⭐⭐⭐ 受限于硬件 |
| **稳定性** | ⭐⭐⭐⭐⭐ 99.9%可用 | ⭐⭐⭐ 依赖本地资源 |
| **维护成本** | ⭐⭐⭐⭐⭐ 零维护 | ⭐⭐ 需要GPU/内存 |
| **费用** | ⭐⭐⭐⭐ 按需付费 | ⭐⭐⭐⭐⭐ 一次性投入 |
| **隐私** | ⭐⭐⭐ 云端处理 | ⭐⭐⭐⭐⭐ 本地处理 |

### 推荐方案

**云端为主 + 本地备用**

- **主力**：阿里云百炼 deepseek-v4-flash（¥0.2/百万token）
- **压缩/辅助**：deepseek-v4-flash（统一模型，省钱）
- **离线备用**：Ollama + llama3.2:3b（本地免费）

## 阿里云百炼配置

### 1. 注册阿里云账号

1. 访问 [阿里云官网](https://www.aliyun.com/)
2. 注册账号并实名认证
3. 开通百炼服务

### 2. 获取API密钥

1. 登录 [百炼控制台](https://bailian.console.aliyun.com/)
2. 进入"API密钥管理"
3. 创建API密钥
4. 复制 `DASHSCOPE_API_KEY`

### 3. 配置环境变量

```bash
# .env 文件
DASHSCOPE_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

### 4. 配置Hermes

```yaml
# config.yaml
model:
  default: deepseek-v4-flash
  provider: alibaba
  context_length: 65536

providers:
  alibaba:
    base_url: https://ws-d2zlnzz8btbed5od.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
    request_timeout_seconds: 120
    stale_timeout_seconds: 90

compression:
  summary_model: deepseek-v4-flash

auxiliary:
  compression:
    model: deepseek-v4-flash
    provider: alibaba
```

## 混合架构配置

### 主力云端 + 本地备用

```yaml
# config.yaml

# 主模型：云端
model:
  default: deepseek-v4-flash
  provider: alibaba

# 回退模型：本地
fallback_model:
  model: llama3.2:3b
  provider: custom:ollama

# 自定义提供商
custom_providers:
  - name: custom:ollama
    base_url: http://localhost:11434/v1
    model: llama3.2:3b
    models:
      - llama3.2:3b
      - qwen3:64k
```

### 降级策略

当云端不可用时，自动降级到本地模型：

1. **检测云端状态** - 定期健康检查
2. **自动切换** - 失败时降级到本地
3. **恢复检测** - 云端恢复后自动切回

## 费用优化

### Token消耗优化

```yaml
# config.yaml
compression:
  enabled: true
  threshold: 0.5
  target_ratio: 0.2
  protect_first_n: 3
  protect_last_n: 20

skills:
  platform_disabled:
    cron:
      - skill1
      - skill2
      # 禁用不需要的skills，减少token消耗
```

### 模型选择策略

| 场景 | 推荐模型 | 原因 |

## 常见问题

### Q: 云端模型响应慢？
A: 检查网络连接，或切换到其他提供商

### Q: 费用超预算？
A: 优化token消耗，禁用不需要的skills

### Q: 云端不可用？
A: 自动降级到本地模型，或手动切换

### Q: 如何切换模型？
A: 使用 `/model` 命令或修改config.yaml

## 最佳实践

1. **统一模型** - 压缩/辅助/主模型用同一个，省钱
2. **禁用skills** - 不用的skills禁用，减少token
3. **定期监控** - 查看费用和性能
4. **备份配置** - 定期备份config.yaml
5. **测试降级** - 确保本地备用可用
